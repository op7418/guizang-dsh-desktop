# Agent Note: 加固 Pilot Harness 插件与桌面边界

Status: implemented

[English](2026-08-17-pilot-harness-boundary-hardening.md) | 中文

## 问题

Pilot Harness 持续增加面向产品的扩展，但此前没有经过一次完整的边界审查。两个呈现插件在 Connection 信任围栏之外注册了精确 HTTP 路由；随附默认模型可能指向已停用的服务商；文件重命名可能覆盖目标；重复悬浮提醒卡会扫描持久日志；第三个布局列也没有进入外壳宽度求解器。桌面启动器还维护第二份依赖树，假定所有非 macOS 平台使用同一种标题栏，并在 Windows 上沿用 POSIX 子进程退出方式。这些接缝让插件停用不彻底、升级更难推理，也让 Windows/Linux 与 macOS 的行为产生实质差异。

## 决策

插件拥有的 Host 操作统一使用带 `authority: 'loopback'` 的命名 Connection RPC 通道；浏览器组件只接收注入的加载／变更回调，不自行构造特权 URL。Worktree 会把每条路径规范到所选 Workspace 内，拒绝链接和不可移植名称，限制枚举规模，并拒绝已存在的重命名目标。Schedule 摘要使用短时、可失效缓存并合并并发请求。保存的默认模型不可路由时，没有历史请求的空白 Session 会采用目录中的第一个可用模型；已经产生请求日志的 Session 则保留其历史选择。

外壳统一拥有四个显式列：导航、对话、右侧栏和详情栏，并用一个让步求解器处理宽度。详情栏最先让步，随后是右侧栏；导航栏永不让步。桌面包直接使用收集好的 Harness 依赖闭包，在随附补丁中禁用 HMR，Linux 使用原生窗口边框，Windows 使用 overlay 标题栏，退出时按平台终止整个进程树，并通过原生平台 CI 矩阵构建。已迁移表面的产品文案保留为本地化标记，主题使用稳定的语义化 `data-pilot-*` 钩子，不再由 CSS 生成英文。

## 考虑过的替代方案

**保留精确同源 HTTP 路由。** 否决：同源不等于 Connection 的权威策略；独立注册的路由可能绕过保护特权能力的 loopback 与 trusted-host 检查。

**打包前再暂存一份 DSH 运行时。** 否决：第二份闭包会产生漂移，也让源码启动和打包启动验证不同的依赖图。

**让 Files 插件在 AppFrame 外自行决定宽度。** 否决：彼此独立的列会把对话区挤到最小宽度以下，并让左侧栏覆盖内容；宽度所有权应属于外壳。

## 后果

停用 Worktree 或 Schedule 呈现插件时，其 UI 与 RPC 注册会一并移除，不再遗留特权路由。文件操作会按 macOS、Windows 与 Linux 的命名规则安全失败。未变化 Session 的提醒悬浮成本有明确上限，已停用服务商也不会再成为新空白 Session 的有效默认项。桌面产物在各自原生操作系统上生成；macOS 仍是本地实际运行过的平台，Windows 与 Linux 新增阻塞式构建／打包测试，但发布前的外壳集成仍需原生 smoke test。剩余的旧主题选择器可以继续逐步迁移到语义钩子，而无需改变本地化内容。
